## 0. Главная задача

**Onet Connect + Poker Combinations + Roguelite Deckbuilding.**

# 4. Игровое поле

Основное поле:

**13 колонок × 8 рядов = 104 плитки.**

Используется обычная колода:

52 уникальные карты:

- 2–10;
- J;
- Q;
- K;
- A;
- четыре масти.

Каждая исходная карта существует в двух экземплярах.

Итого:

52 × 2 = 104 плитки.

Это 52 исходные пары.

ВАЖНО:

Количество физических плиток на новом поле всегда 104.

Магазин может изменять состав колоды, но не добавляет физические клетки на поле.

Например, преобразование пары двоек в пару королей заменяет существующие плитки.

Размер поля не изменяется.

- трефы — зелёные;

Не использовать стандартные два цвета как единственный способ различать масти.

Дизайн:

- белая или кремовая карточка;
- большая масть на центральной части;
- крупный ранг внутри масти либо поверх контрастной плашки;

Карты должны различаться издалека даже на поле из 104 плиток.

У улучшенных карт появляются дополнительные признаки:

# 6. Главное правило Onet Connect

Игрок выбирает две карты с одинаковыми:

- рангом;
- мастью.

Если между ними можно провести линию максимум с двумя поворотами на 90 градусов, соединение разрешено.

Линия может идти:

- горизонтально;
- вертикально;
- с одним поворотом;
- с двумя поворотами;
- через пустые клетки;
- вокруг внешнего края поля.

Нельзя проходить через занятую клетку, кроме конечной выбранной карты.

Реализовать универсальный PathFinder на основе BFS или аналогичного корректного алгоритма.

Для поиска использовать виртуальную пустую границу вокруг поля.

Стандартный лимит:

```js
maxTurns = 2;
```

Лимит может изменяться джокерами и боссами.

Например:

- обычное соединение: 2 поворота;
- полезный джокер: 3 поворота;
- проклятый джокер: 1 поворот;
- особый босс: 1 поворот.

В перспективе допускается до 4 поворотов.

Проверять доступность пути непосредственно в игровом движке, а не только визуально.

# 7. Два способа удаления пары

Реализуй два действия.

## A. Собрать карту

Левая кнопка мыши.

Игрок выбирает две одинаковые карты.

Если соединение допустимо:

1. Появляется светящаяся линия.
2. Обе плитки удаляются.
3. Одна карта добавляется в покерную руку.
4. Срабатывают эффекты карты и джокеров.
5. Поле перестраивается по текущему правилу движения.
6. Проверяются доступные пары.

Это основное действие.

## B. Уничтожить пару

Правая кнопка мыши.

Игрок выбирает две одинаковые карты.

Если соединение допустимо:

1. Карты уничтожаются.
2. В покерную руку ничего не добавляется.
3. Расчищается игровое пространство.
4. Применяется движение поля.
5. Срабатывают специальные эффекты уничтожения.

На уничтожение есть ограниченный ресурс.

Начальное значение:

```js
banishes = 2;
```

На смартфоне создать переключатель режима:

- СОБРАТЬ;
- УНИЧТОЖИТЬ.

По умолчанию — СОБРАТЬ.

Правый клик на ПК не должен открывать браузерное контекстное меню над игровым полем.

Это бесплатно.

После автоматического перемешивания гарантировать хотя бы одну доступную пару согласно текущему лимиту поворотов.

Начальный ресурс:

```js
manualShuffles = 2;
```

Это расходуемая способность этапа.

Нужно для поиска более выгодных комбинаций.

После перемешивания состав карт и количество плиток сохраняются.

Не менять улучшения и характеристики карт.

Гарантировать существование доступного соединения.

Обработка анимации не должна расходовать перемешивание дважды.

# 9. Покерная рука

Под игровым полем расположить пять слотов:

```text
[  ] [  ] [  ] [  ] [  ]
```

Каждое успешно собранное соединение добавляет одну карту.

Пример:

1. K♥
2. A♠
3. Q♦
4. K♣
5. J♠

Получается пара королей.

После заполнения пяти слотов:

1. Заблокировать ввод.
2. Определить комбинации.
3. Рассчитать базовые очки.
4. Применить улучшения карт.
5. Применить джокеров.
6. Применить множители.
7. Анимировать подсчёт.
8. Прибавить результат к очкам этапа.
9. Уменьшить количество оставшихся покерных рук.
10. Очистить руку.
11. Продолжить испытание или завершить этап.

Никаких дополнительных кнопок для розыгрыша полной руки не требуется.

Позже разрешить специальным эффектам досрочное разыгрывание неполной руки, но по умолчанию всегда пять карт.

# 10. Ограничение количества рук

Вместо времени используется ограничение на количество покерных комбинаций.

Начальные значения для первого баланса:

```js
handsPerStage = 4;
handSize = 5;
```

Это значит, что игрок может четыре раза заполнить руку и получить очки.

Для одной полной руки обычно требуется пять соединений.

Некоторые способности увеличивают число рук:

- +1 рука;
- +2 руки;
- +1 рука за штраф;
- дополнительные карты в руку.

Если все руки потрачены, а цель не достигнута — поражение.

Если целевые очки достигнуты — победа, даже если остались неиспользованные руки.

# 11. Дублирование карт

Это одна из основных особенностей игры.

Добавить улучшение:

**Эхо ×2**

Если такая карта получена через соединение, вместо одной карты в руку добавляются две одинаковые.

Пример:

Обычная пара:

```text
K♥ + K♥ → K♥
```

Улучшенная:

```text
K♥ + K♥ → K♥, K♥
```

Это позволяет создавать множество необычных комбинаций.

Если в руке остался только один слот, а эффект выдаёт две карты:

- первая помещается в текущую руку;
- вторая переходит в небольшой резерв на следующую руку;
- резерв ограничен и явно показан игроку;
- карта не должна пропадать молча;
- если следующей руки не будет, неиспользованная резервная карта превращается в заранее определённый небольшой бонус очков.

Это поведение вынести в CONFIG и подробно объяснить игроку.

# 12. Покерные комбинации

В этой игре разрешены фантастические комбинации, потому что колода может содержать несколько одинаковых карт.

Главная особенность:

**Комбинации можно совмещать.**

Пример:

```text
K♥ K♥ K♥ K♥ J♥
```

Это одновременно:

- каре;
- флеш.

Значит начисляются бонусы за оба достижения.

Пример:

```text
K♥ K♥ K♥ J♥ J♥
```

Это:

- фулл-хаус;
- флеш.

Пример:

```text
A♦ A♦ A♦ A♦ A♦
```

Это:

- пять одинаковых;
- флеш.

Создать особую комбинацию:

**Суперкаре / Five of a Kind.**

Она сильнее обычного каре.

# 13. Правила определения комбинаций

Реализовать следующие категории:

- старшая карта;
- пара;
- две пары;
- сет;
- стрит;
- флеш;
- фулл-хаус;
- каре;
- стрит-флеш;
- роял-флеш;
- пять одинаковых;
- фулл-хаус одной масти;
- пять одинаковых одной масти.

Система расчёта должна разделять независимые свойства руки:

1. Повторения рангов.
2. Последовательность рангов.
3. Совпадение мастей.
4. Особые фантастические комбинации.
5. Улучшения карт.
6. Эффекты джокеров.

Для повторений рангов выбирать только самую сильную категорию.

Например, каре не должно автоматически давать награды ещё и за пару с сетом.

Но каре может одновременно получить бонус флеша.

Стрит и флеш могут сочетаться.

Для стрит-флеша разрешить дополнительную синергию.

Каждая синергия должна иметь отдельный ID, чтобы один эффект не начислялся дважды.

Стрит A-2-3-4-5 должен распознаваться правильно.

# 14. Scoring Engine

Реализовать собственную расширяемую систему подсчёта.

Основные переменные:

```js
chips
mult
xMult
finalScore
```

Общая формула:

```js
finalScore = Math.floor(
    chips * mult * xMult
);
```

Все расчёты должны происходить в фиксированном порядке:

1. Определение основной комбинации по рангам.
2. Дополнительные независимые комбинации.
3. Базовая стоимость пяти карт.
4. Бонусы за способ соединения.
5. Индивидуальные улучшения карт.
6. Джокеры, срабатывающие на карту.
7. Джокеры, срабатывающие на собранную руку.
8. Аддитивные множители.
9. Мультипликативные множители.
10. Специальные эффекты босса.
11. Итоговый результат.

Подсчёт сделать событийным.

Каждый шаг должен записываться в score timeline.

Например:

```text
Карты: +49
Каре: +450
Флеш: +170
Золотая карта: +25
Джокер: +40
Множитель: +2
Редкий джокер: ×1.5

ИТОГО: 2202
```

Цифры — стартовые ориентиры для балансировки.

Не копировать таблицы Balatro дословно. Разработать собственные численные параметры, используя справочник как пример архитектуры.

- A даёт 11.

Все величины вынести в конфигурацию.

Сразу предусмотреть возможность изменения уровней комбинаций, цен и множителей без переписывания логики.

# 16. Бонусы за геометрию соединения

Это важное уникальное отличие нашей игры.

Сохранять для каждой собранной карты метаданные:

```js
{
    rank,
    suit,
    turnsUsed,
    usedOuterBorder,
    modifiers
}
```

При подсчёте учитывать:

- соединение без поворота;
- один поворот;
- два поворота;
- использование внешней границы.

Начальные бонусы:

- 0 поворотов: +5;
- 1 поворот: +10;
- 2 поворота: +15.

Добавить джокеров, которые реагируют на геометрию.

Например:

- бонус за прямую;
- большой бонус за два поворота;
- бонус за путь вокруг поля;
- бонус за сбор карт с разных краёв.

Если доступно несколько допустимых путей, PathFinder должен возвращать выбранный игровой путь детерминированно, предпочитая меньшее число поворотов, затем меньшую длину, если джокер специально не меняет правило.

Не разрешать игроку намеренно получать бонус за два поворота, когда существует прямая линия, если соответствующая механика выбора маршрута не реализована отдельно.

# 17. Колода из фиксированных 52 пар

Использовать 52 исходных идентификатора пар.

Каждая исходная пара имеет:

```js
{
    blueprintId,
    originalRank,
    originalSuit,
    currentRank,
    currentSuit
}
```

После преобразования карт обновляется currentRank/currentSuit.

На новом поле создать по две плитки на каждый blueprintId.

Таким образом физических плиток всегда 104.

При преобразовании:

```text
2♥ → K♥
```

Две плитки исходной двойки становятся двумя королями.

Теперь одинаковых K♥ на поле может быть четыре или больше.

Визуальное совпадение определяется по текущим rank и suit, а не по blueprintId.

Для первой реализации улучшения одной карточной идентичности должны применяться ко всем экземплярам одинакового currentRank/currentSuit. Показывать игроку количество копий, которое будет затронуто.

Не создавать скрыто различающиеся по эффектам плитки, которые выглядят абсолютно одинаково.

# 18. Улучшения обычных карт

Добавить систему Card Enhancements.

Первый каталог:

1. Золотая — увеличивает очки карты.
2. Серебряная — добавляет множитель.

5. Огненная — дополнительный урон по ограничениям босса или бонус к очкам.
6. Ледяная — увеличивает бонус за выбранную масть.
7. Стеклянная — сильный множитель, но риск временной потери свойства.
8. Магнитная — усиливается при сборе карт того же ранга.
9. Королевская — дополнительный бонус за J/Q/K.

# 19. Выбор карт для улучшения

В магазине создать интерфейс выбора.

Игроку предлагается случайная выборка из 5 карт его колоды.

Редкое улучшение расширяет предложение до 10 карт.

Игрок:

1. Выбирает покупаемое улучшение.
2. Получает 5 или 10 предлагаемых карточных идентичностей.
3. Выбирает нужную.
4. Видит текущие свойства.
5. Видит будущий эффект.
6. Подтверждает покупку.
7. Колода изменяется.
8. Изменение сохраняется до конца забега.

Некоторые джокеры позволяют улучшить сразу несколько разных карт за одну покупку.

Например:

**Мастер кузницы**

При покупке одного улучшения можно дополнительно выбрать ещё две подходящие карточные идентичности.

Все три должны получить одинаковое улучшение.

Не тратить деньги трижды.

Учитывать ограничения совмещения.

# 20. Система Джокеров

Разработать отдельный JokerManager.

Джокеры являются пассивными предметами текущего забега.

Базовое количество слотов:

```js
jokerSlots = 3;
```

Некоторые эффекты добавляют слоты.

Например:

- +1 слот;
- +2 слота, но −1 рука;
- дополнительный временный слот на один этап.

В UI показывать слоты джокеров.

При наведении на джокера:

- название;
- редкость;
- эффект;
- условие срабатывания;
- текущие накопленные бонусы;
- стоимость продажи;
- совместимость с другими эффектами.

# 21. Категории джокеров

Разделить джокеров по категориям.

### Очковые

Увеличивают chips.

### Множители

Увеличивают mult и xMult.

### Экономические

Добавляют золото.

### Геометрические

Влияют на число разрешённых поворотов или на награду за маршрут.

### Коллекционные

Реагируют на ранги и масти карт.

### Комбинационные

Усиливают покерные комбинации.

### Манипуляторы колоды

Дублируют, преобразовывают или улучшают карты.

### Рискованные

Дают большой бонус, но накладывают штраф.

### Легендарные

Меняют одно из основных правил игры.

# 27. Структура забега

Забег состоит из последовательных этапов.

Первое испытание:

всегда статическое поле.

Второе:

случайное движение из разблокированных вариантов.

Третье:

босс с особым правилом.

После победы над третьим этапом:

- показать завершение первой главы;
- открыть награду;
- предложить продолжить забег;
- открыть новый постоянный контент, если выполнены условия.

Игра не должна останавливаться после трёх этапов.

Игрок может продолжать бесконечно на рекорд.

Дальше формировать главы с более разнообразными движениями и случайными боссами.

По мере достижения целей разблокируются новые механики.

В поздней игре могут появляться последовательности из 7–8 различных движений в одной главе.

Первые семь:

7. Левая половина вправо, правая влево.

Дополнительно реализовать:

8. Чередование столбцов вверх/вниз.
9. Чередование рядов влево/вправо.
10. Сдвиг по периметру по часовой стрелке.
11. Сдвиг периметра против часовой стрелки.

Для движений по периметру использовать циклическое перемещение содержимого существующих клеток; для змейки — заранее определённый порядок обхода.

Каждый тип движения имеет ID, название, краткое описание и собственную иконку.

В начале этапа показывать его правило.

# 29. Разблокировка движений

В первом запуске доступны:

- статичное поле;
- движение вниз;
- движение вверх.

Остальные открываются через достижения.

Например:

- завершить 3 этапа;
- завершить 5 этапов;
- собрать флеш;
- собрать каре;
- завершить первый забег;
- пройти определённого босса.

Открытые движения сохраняются навсегда.

При генерации этапа выбирать только движения из списка открытых.

Первый этап забега всегда статичный.

Не использовать непроверенные или неразблокированные движения.

# 31. Ночной Джокер — визуальный эффект

Сделать полноценную анимацию тёмного поля.

Не применять тяжёлый постпроцессинг.

Учитывать мобильные устройства.

Не затемнять текст интерфейса и объяснение правил.

Сделать возможность уменьшить интенсивность визуального эффекта через настройки доступности, но не отключать игровой штраф целиком.

# 46. Seeded RNG

Для каждого забега использовать seed.

Все игровые случайности проводить через отдельный SeededRandom:

- генерация поля;
- стартовые усиления;
- предметы магазина;
- рероллы;
- движение поля;
- боссы;
- случайные эффекты.

Не использовать Math.random напрямую в игровой логике.

Seed должен сохраняться.

Один seed при одинаковых действиях должен воспроизводить одинаковое состояние.

Для декоративных частиц разрешается независимый визуальный RNG.

# ГЛАВНОЕ ТРЕБОВАНИЕ

Не делай обычную копию Balatro с другим внешним видом.

Это собственная игра с собственной центральной механикой.

Главная особенность:

**Игрок не получает случайные карты в руку. Он самостоятельно добывает нужные карты из пространственного поля Onet Connect.**

Для этого он:

- ищет доступные пары;
- планирует будущие соединения;
- уничтожает мешающие карты;
- использует перемешивания;
- меняет состав фиксированной колоды;
- улучшает конкретные карточные идентичности;
- комбинирует джокеров;
- адаптируется к движению поля;
- обходит ограничения боссов.

Сделай сначала стабильную игровую систему, затем добавь качественные анимации и богатый контент.

Итог должен быть игрой, которую можно запустить, пройти несколько этапов, улучшить колоду, победить босса и продолжить забег ради рекорда.

Начинай с проверки существующих файлов проекта и исследования Balatropedia, затем переходи непосредственно к реализации. Не ограничивайся архитектурным описанием — создавай и тестируй рабочий код.
